Publicação pública por Período Letivo

Este arquivo registra a arquitetura desejada para permitir publicações separadas por PL sem obrigar o aluno a escolher manualmente o período letivo na agenda pública. A decisão principal é manter uma única agenda_publica.html e deslocar a inteligência de roteamento para um catálogo/configuração pública.

Decisão central

  • A agenda publicada continua sendo uma única página: agenda_publica.html.
  • O aluno não deve decidir o PL por conta própria na interface.
  • O PL ativo para o aluno deve sair de um catálogo público com uma publicação padrão.
  • Links com ?pl=... podem existir futuramente para uso interno, auditoria ou divulgação dirigida.

Arquivos-base já preparados

  • publicacoes/publicacao_config.json
  • publicacoes/catalogo_publicacoes.json
  • tools/publish_online.py
  • js/agenda_publica.js

Ponto de UX preservado

Mesmo quando existirem vários PLs publicados simultaneamente, a experiência padrão do aluno deve continuar simples: abrir a agenda pública e ver o PL correto sem precisar interpretar siglas institucionais.

Lógica de resolução da agenda pública

Etapa Regra
1. Carregar configuração Ler publicacoes/publicacao_config.json.
2. Carregar catálogo Ler publicacoes/catalogo_publicacoes.json.
3. Escolher a publicação Usar a publicação marcada como padrão para estudantes.
4. Carregar o JSON Buscar o arquivo indicado em defaultPublication.jsonPath.
5. Fallback Se o catálogo não existir ou falhar, usar o modelo legado com alocacoes_publicas.json na raiz.

Comportamento esperado do script Python

  1. Ler o payload exportado e detectar o PL a partir de plan e settings.
  2. Consultar publicacoes/publicacao_config.json.
  3. Se o modo for legacy_single_file, publicar em alocacoes_publicas.json.
  4. Se o modo for plan_directory, resolver a pasta pelo template configurado.
  5. Criar a pasta automaticamente se ela ainda não existir.
  6. Num passo futuro, também atualizar o catálogo público para apontar qual PL fica visível aos estudantes.

Chaves ainda não ativadas

  • Troca automática de layoutMode para plan_directory.
  • Atualização automática do catálogo de publicações pelo script Python.
  • Interface administrativa para escolher qual PL fica ativo para os alunos.
  • Links institucionais por PL para uso externo controlado.

A próxima etapa mais sensível da transição não é publicar por PL, e sim isolar completamente a agenda discente legada sem quebrar a URL já usada em produção.

  • agenda_discente.html foi preservada e restaurada nesta branch.
  • Existe um snapshot completo da versão da main em _backups/agenda_discente_main_snapshot_20260328.
  • Nenhuma remoção lenta de arquivos deve começar antes do teste manual da agenda_discente.html nesta branch.
  • Se o teste falhar, a prioridade é retroagir e manter o legado compartilhando arquivos por mais tempo.
  • Se o teste passar, a etapa seguinte recomendada é isolar dependências da agenda discente em estrutura própria, sem alterar sua URL pública.

Próximo passo recomendado

Quando a coordenação decidir publicar simultaneamente dois PLs reais, o próximo pacote de implementação deve fazer duas coisas ao mesmo tempo:

  1. ativar o modo plan_directory no arquivo de configuração;
  2. ensinar o publish_online.py a atualizar o catalogo_publicacoes.json com a publicação padrão.

Assim, a separação por PL entra de forma elegante, sem multiplicar HTMLs e sem transferir a decisão operacional para o aluno.
